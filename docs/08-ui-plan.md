# 08 · 后台界面改造计划

> 起因：五个问题——密码长度、浏览器角标、页面丑、只有英文、没有防呆与引导。
> 本文是执行计划。调查基于当前代码（`03843ff`），所有行号都对着代码核过。

---

## 0. 调查结论：比表面看到的更多

五个问题里有三个，根因不在"没做"，而在"做了但没接上"。先列出来，因为它们改变了工作量判断：

| 发现 | 位置 | 后果 |
|---|---|---|
| **`Test connectivity` 对 webhook / 钉钉 / 飞书 / Slack webhook / 企微 webhook 根本不发网络请求**，直接返回 `configuration is valid (a webhook has no side-effect-free probe)` | `webhook.go:112`、`dingtalk.go:124`、`feishu.go:115`、`slack.go:115`、`wecom.go:126` | **界面上绿色的 "OK" 可能对应一个从未连通过任何东西的通道。** 这是所有问题里最危险的一个 |
| **"New channel" 表单输入一个已存在的名字会静默改掉那条在线通道** | `channels.go:109`（save 是 upsert，无重名检查） | 想新建，结果改坏了正在用的通道，没有任何提示 |
| **必填红星号是装饰性的**：模板把 `data-required` 放在包裹的 `.field` div 上，JS 却在 `input` 上查这个属性 | `channels.html:78` vs `app.js:115-118` | 生成的输入框从来没有 `required`，浏览器原生校验从不触发 |
| **`channels.html:15` 有内联 `style="min-width: 260px;"`**，而 CSP 是 `style-src 'self'` 不含 `unsafe-inline` | `channels.html:15`、`admin.go:202` | 这条样式**现在就是被浏览器拒绝的**，只是没人注意 |
| **`/admin/audit` 在审计关闭时显示 "Nothing yet."** | `ui.go:527-548` | 与"审计正常但没有记录"完全无法区分 |
| **`error.html` 永远只有一个链接："Back to channels"** | `error.html:5` | 从投递页出错，也让你回渠道页 |
| **`?ok=` 闪现消息从不消费** | `ui.go:552-560` | 刷新页面会无限重复"Saved X" |
| **管理员密码没有任何修改或找回入口** | 路由表 `admin.go:131-191` 无相关端点 | 忘了密码只能改数据库或写配置文件 |

**另外两处只有翻译时才会暴露的：**

- `app.css:27` 是全文件**唯一**一条字体声明，正文、标题、表格、按钮、代码全都用它：`ui-monospace, SFMono-Regular, Menlo, Consolas, monospace`。这些字体**都没有中文字形**——中文会回退到另一个字体，一行里混两种字形，1.5 的行高对中文也偏挤。
- 模板函数 `since` / `stamp` 在全局 `FuncMap` 里注册一次，**拿不到每次请求的语言**，所以 "just now / 5m ago" 无法翻译。

## 1. 工作量实数

翻译面（不是估计，是数出来的）：

| 位置 | 字符串点位数 | 去重后 |
|---|---|---|
| 模板（10 个文件，708 行） | 148 | ~120 |
| Go 代码（`writeError` 62 + `renderError` 8 + 标题 8 + 相对时间 4 + 审计详情 10 + 其他 3） | 95 | ~74 |
| `app.js` | 20 | ~18 |
| **合计** | **~263** | **~212** |

**现有的 i18n 做法不能扩展。** `apidocs.html` 用的是逐字符串 `{{if .Zh}}…{{else}}…{{end}}`，一个字符串两个分支。照搬到其余 9 个模板就是 ~296 个分支，而且没有任何机制保证两边同步。它还有四个更硬的问题：语言只存在 query string 里（点任何导航链接就丢）、`pageData` 根本没有语言字段、模板函数拿不到语言、JS 里的 20 个字符串服务端够不着。

## 2. 决策（已确认）

| | |
|---|---|
| 密码最小长度 | **8 位**（当前 12） |
| 界面默认语言 | **中文**，可切英文，选择用 cookie 记住 |
| 视觉改版幅度 | **大幅重做**：配色、左侧边栏导航、内联 SVG 图标、面包屑、统计卡片、响应式断点 |
| 保留 | 无框架、无 CDN、无外部字体（CSP 与"断网时后台还能用"两条约束不变） |

## 3. 执行计划

分成五段。**关键排序考虑**：第 3 段和第 4 段都要动全部模板，所以合并进行——每个模板只碰一次，而不是先翻译再改版碰两次。

### 第 0 段 · 先修已确认的缺陷（不依赖其他任何工作）

这些是独立的、小的、现在就是错的。先修掉，后面的改动就建立在正确的行为上。

| # | 修什么 | 位置 |
|---|---|---|
| 0.1 | 内联 `style` 移进 `app.css`（CSP 现在就拒绝它） | `channels.html:15` |
| 0.2 | 必填标记真正生效：JS 改查 `.field` 上的 `data-required`，并给 input 设 `required` | `app.js:115-118` |
| 0.3 | 密码最小长度 12 → 8（Go 常量 + 模板 `minlength` + 错误文案 + 测试） | `setup.go:44`、`setup.html:20,24` |
| 0.4 | 新建通道时**不预选任何类型**，用 `disabled selected` 占位项 "选择类型…" | `channels.html:60`、`ui.go:342` |
| 0.5 | 通道重名：保存时若名字已存在且不是编辑模式，返回 409 并要求确认；前端弹确认说明"这会覆盖在线通道 X" | `channels.go:109`、`app.js` |
| 0.6 | `error.html` 的返回链接按来源页给（投递页回投递页），或至少给"返回"而非写死渠道页 | `error.html:5`、各 `renderError` 调用点 |

**验收**：`go test ./...` 全绿；0.1 用浏览器控制台确认无 CSP 违规；0.5 有测试覆盖"重名保存被拒"。

### 第 1 段 · i18n 基础设施（不动模板）

先建管道，不翻译任何东西。这一段结束时界面看起来完全没变。

**新增 `internal/admin/i18n`**：

```go
// Messages 是一个语言的完整文案表。
//
// 用结构体而不是 map：漏翻一条是编译错误，而不是运行时显示空白。
type Messages struct {
    NavChannels   string
    NavDeliveries string
    // …约 212 个字段
}

var zh = Messages{NavChannels: "渠道", …}
var en = Messages{NavChannels: "Channels", …}

func For(lang string) *Messages
```

**语言解析**（`internal/admin/lang.go`）：
- 顺序：`?lang=` → cookie `nr_lang` → 默认 `zh`
- 切换链接写 cookie 并 302 回当前页（去掉 `lang` 参数），**这样选择能跨导航和跨重定向存活**——这是现有实现最大的漏洞
- `pageData` 增加 `Lang string` 和 `T *i18n.Messages`

**模板函数语言化**：`since` / `stamp` 改成返回闭包，`FuncMap` 每次渲染按语言构建。`since` 的中文是"刚刚 / 5 分钟前 / 3 小时前"。

**JS 字符串通道**：沿用页面里已有的 `<script type="application/json" id="catalog">` 模式，加一个 `#i18n` 数据块，服务端按当前语言渲染。JS 读它。四个 `window.confirm` 的插值（通道名、key 名、投递 ID）在 JS 侧拼接。

**`<html lang>` 动态化**（`layout.html:3` 现在写死 `en`）。

**验收**：新增 `internal/admin/i18n` 的测试——`zh` 和 `en` 两个结构体的**每个字段都非空**（漏翻即失败）；语言 cookie 往返测试；`?lang=` 优先级测试。

### 第 2 段 · 视觉重设计 + 翻译（逐模板，每个只碰一次）

这是最大的一段。按模板推进，每个模板一次改到位。

**2.1 设计系统（`app.css` 重写）**

- **排版**：正文改系统无衬线（`-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`），代码/ID/令牌保持等宽。**中文字体必须显式列出**，否则中文回退不可控——这是现在最大的可读性问题。
- **配色**：保留深色基调，重新设计层次（背景/表面/浮起三级），语义色（成功/警告/危险/信息）成对给出前景+背景。
- **间距**：建立 4px 基数的间距刻度，替掉现在散落的裸 px。
- **令牌化**：现在有 3 个颜色是硬编码的十六进制（`#0d1117`、`#06121f`、`#141c25`），全部收进变量。

**2.2 布局与导航**

- 顶部栏 → **左侧边栏**（品牌、导航、底部账号与登出）
- 页头组件：面包屑 + 标题 + 右侧操作区
- 响应式断点：窄屏侧边栏收起为顶部栏（现在**一条 media query 都没有**）

**2.3 图标**：内联 SVG 组件（模板里一个 `{{define "icon-xxx"}}` 集合）。CSP 允许 `img-src 'self' data:`，内联 `<svg>` 属于文档流不受限。**不用图标字体**——`font-src` 没声明，会回退到 `default-src 'self'`，能自托管但没必要。

**2.4 逐模板改造**（10 个文件）

每个模板同时完成：结构改版 + 全部字符串换成 `{{.T.Xxx}}` + 空状态改造（见第 3 段）。

顺序（从简单到复杂，先建立模式）：`error.html` → `login.html` → `setup.html` → `audit.html` → `keys.html` → `deliveries.html` → `delivery.html` → `channels.html` → `apidocs.html` → `layout.html`

`apidocs.html` 特殊：它已经有双语，改造时**把它的 `{{if .Zh}}` 全部换成消息表**，并解决它现在的两个问题——`samples/*.txt` 里的英文注释没有中文版、7 个 `Note` 字段只有英文。

> **后续已完成**（不在本计划范围内，是之后追加的）：渠道表单的字段标签与说明
> （`internal/channel/*/config.go` 的 `ParamSpec.Label`/`Desc`，64 条）和 7 个代码示例的注释。
> 参数文案用 **map 而不是结构体**，这是刻意的例外：结构体的好处是漏翻即编译错误，
> 代价是**加一个渠道类型要去改 i18n 包**，而那正好是本项目最硬的一条边界
> （新渠道 = 新包 + 一行 import）。所以保证从编译器挪到了测试，见 `paramcopy_test.go`。
> 示例则按语言分目录，并用一条「剥掉注释后逐行相同」的测试防止两份代码漂移。

**2.5 Go 侧字符串**：95 个点位换成从消息表取。`writeError` 的 42 条去重消息、8 个页面标题、10 条审计详情。审计详情（"created" / "deleted" / "disabled"）**建议保持英文**——它们是审计记录，不是界面文案，翻译会让同一张表混两种语言且历史记录无法统一。这一点在计划里明确，不留给实现时随手决定。

**验收**：每个模板改完跑一次现有的 UI 测试（`ui_test.go`、`apidocs_test.go` 对真实 HTML 断言，会立刻抓到结构破坏）；新增一条测试断言**渲染出的页面里没有残留的英文字面量**（对中文模式）。

### 第 3 段 · 防呆与引导

**3.1 空状态全部重写**（现在 7 处，多数只说"没有"不说"怎么办"）

| 位置 | 现在 | 改成 |
|---|---|---|
| 渠道 | "No channels configured. Deliveries will fail until there is one." | 图标 + 一句说明 + **"新建渠道"按钮**（现在按钮在页头，空状态里够不着） |
| 投递 | "Nothing matches."（**无数据和筛选无结果共用**） | 分两种：从没发过 → 引导去建渠道和 Key；筛选无结果 → "没有匹配的投递，清除筛选" |
| 审计 | "Nothing yet."（**与审计关闭无法区分**） | 分两种：未启用 → 说明；启用但空 → 说明什么会被记录 |
| 密钥 | 已经不错 | 保留，补一句"接下来用它调 API"的链接 |
| 投递详情无尝试 | "No attempts recorded." | 解释零尝试的三个原因（熔断/配额/限流）并链到 API 文档对应小节 |

**3.2 首次登录引导**

管理员创建成功后，落到一个**上手清单**页（不是直接跳渠道页）：

```
□ 创建一个渠道        → /admin/channels
□ 创建一个 API Key    → /admin/keys
□ 发一条测试通知      → 页面内直接发
□ 看它送达            → /admin/deliveries
```

完成项打勾并持久化（`meta` 表）。全部完成后清单收起，不再出现。**这是"没有实例流程"的直接答案。**

**3.3 界面上发测试通知（本计划最高价值的一项）**

现在从"配置好了"到"确认能送达"之间，**必须离开界面去终端跑 curl**。而且 `Test connectivity` 对五种通道类型根本不发请求却返回绿色 OK。

两件事一起做：

- **诚实化 `Test` 的结果**：区分"验证了配置"和"真的连通了"。对不发请求的类型，结果显示为**中性色**并明确写"未发起网络请求——这类通道没有无副作用的探测方式"，而不是绿色 OK。
- **新增"发送测试通知"**：在渠道页和上手清单里，选一个通道、填标题正文、真的走一遍完整投递链路（入队 → worker → 通道 → 审计），然后**跳转到那条投递的详情页**。这样"配置好了"和"真的能送达"之间不再有断层。

  实现上需要给 admin 的 `Deps` 加一个 `Enqueuer`（和 `api.Deps.Queue` 同接口）——现在 `DeliveryStore` 接口**故意**不含入队，这一点要在计划里写明为什么现在要加、以及边界（只能发测试通知，不能发任意通知，避免后台变成第二个发送入口）。

**3.4 校验错误就地显示**

现在：所有错误挤在表单**最底部**一个段落里、用 schema 名而非界面标签（"parameter `host` is required" 而字段标着"SMTP 服务器"）、多条错误被 `errors.Join` 连成一行 run-on 句子（`.flash` 没有 `white-space` 规则）。

改成：错误按字段就地显示在对应输入框下方、用标签名、多条错误渲染成列表、出错时滚动并聚焦到第一个错误字段。

**3.5 其他防呆**

- 通道表单有未保存改动时离开/取消 → 确认
- "Test connectivity" 在未保存时 → 明确提示"先保存再测试"（现在是服务端回 "no channel with that name"，读起来像 bug）
- 编辑一个已被删除的通道 → 明确提示并给"新建"入口（现在表单空白但标题是"编辑 X"，保存会**创建**）
- 列表参数（`to`、`at_mobiles`）→ 说明是逗号分隔（现在只靠 JS 隐式处理，文案里没写）
- 密钥启用/禁用 → 补反馈（现在**完全没有**，而这是改"什么能认证整个服务"的操作）

**3.6 管理员密码修改**

现在完全没有入口。补一个"修改密码"页 + 端点，需要验证当前密码。**找回**不做——那需要邮件或第二个凭据，超出范围；文档里写明"忘了只能改数据库"。

**验收**：每条防呆配一个测试；"发送测试通知"端到端跑通（真的入队、真的投递、真的出现在投递列表）。

### 第 4 段 · 浏览器角标与其他

- **favicon**：`static/favicon.svg`（内联 SVG，`img-src 'self'` 允许）。`registerAssets` 会自动按文件注册路由，**Go 侧零改动**，只需在 `layout.html` 加一行 `<link rel="icon">`。
- **标题格式**：现在是 `{{.Title}} · NotifyRelay`。中文界面下改成 `渠道 · 信使中枢`，`<html lang>` 同步。
- `theme-color` 与 `color-scheme: dark`，让浏览器 UI 与页面配色一致。
- 可选（需你确认）：**浅色主题**。现在只有深色，且没有 `prefers-color-scheme`。做的话是多一套令牌 + 一个切换，工作量不大但会让上面的配色工作翻倍。

**验收**：浏览器标签页显示图标与中文标题。

### 第 5 段 · 验证

- `go vet` / `go test ./...` 全绿
- 新增测试：i18n 完整性（两个语言表无空字段）、语言 cookie 往返、空状态分叉、重名保存被拒、测试通知端到端
- **变异验证**：至少对"必填标记真正生效"和"重名保存被拒"两条做——故意改坏实现，确认测试会失败
- 浏览器实测：中英文各走一遍完整流程（建渠道 → 建 Key → 发测试通知 → 看投递）
- 更新 `docs/07-api.md`（新增端点）、README 的后台截图描述

## 4. 不建议做的

- **不引入前端框架**（React/Vue）。CSP 是 `script-src 'self'`，构建产物要自托管；而且后台在断网时也必须能用，一个需要构建步骤的前端会破坏这条。
- **不引入图标库**（Font Awesome 等）。内联 SVG 足够，且不增加依赖。
- **不做审计详情的翻译**（理由见 2.5）。
- **不做密码找回**（超出范围，需要第二凭据或邮件）。
- **不做多用户 / RBAC**。当前是单管理员模型，这是有意的最小设计，改它需要单独决策。

## 5. 风险

| 风险 | 应对 |
|---|---|
| 改版破坏现有 UI 测试 | `ui_test.go` / `apidocs_test.go` 对真实 HTML 断言——**这是好事**，它们会在改坏时立刻失败。逐模板推进，每个模板改完就跑一次 |
| 翻译漏项 | 消息表用结构体，漏字段是编译错误；再加一条测试断言两个语言表无空值 |
| 视觉改版范围失控 | 先定设计令牌再改模板；每个模板改完在浏览器里看一眼，不攒到最后 |
| 第 2 段工作量最大 | 它同时做改版和翻译，但**合并做比分开做省一遍全部模板的返工**——这是刻意的排序，不是偷懒 |

## 6. 建议的执行顺序

```
第 0 段（缺陷修复）     ← 独立，可立即开始
   ↓
第 1 段（i18n 管道）    ← 不碰模板
   ↓
第 2 段（改版+翻译）    ← 最大，逐模板
   ↓
第 3 段（防呆+引导）    ← 依赖第 2 段的模板结构
   ↓
第 4 段（角标等）       ← 小
   ↓
第 5 段（验证）
```

每段结束都可以停、可以验收、可以提交。**第 0 段和第 1 段做完就已经能交付一次**——前者修掉真 bug，后者为后面铺路。
